练习包里有什么

练习使用虚构的 JSON 工单明细，避免安装 Excel 处理库。它演示的去重、统计和校验方法也适用于表格任务，真实 Excel 接入需另行实现字段读取。

Python 3.9+，只用标准库。Skill ZIP 只包含能力目录，练习数据在完整练习包中。这里没有空 assets/，因为练习不需要模板。

python3 ticket-daily-report/scripts/pipeline.py \
  --input fixtures/normal.json --date 2026-10-10 --out result-first

输出目录须不存在。通过后生成 report.json、report.txt、evidence.json。预期为 5 单，完成 3 单、待处理 2 单，完成单平均耗时 65 分钟。缺字段或重复 ID 内容冲突时停止，并且不创建成功结果。

给 Qoder 的练习提示词
请使用 ticket-daily-report Skill，对练习包 fixtures/normal.json 生成日报。统计日期为 2026-10-10，输出到一个新的结果目录。先读取数据契约与业务规则，再运行 scripts/pipeline.py。校验失败时停止并说明原因，校验通过后交付日报和 evidence.json。我会用 expected/2026-10-10.json 核对结果。

怎样在 Qoder 中加载

当前 Qoder：在扩展的技能页中添加技能，导入完整 Skill ZIP，确认出现在已安装中。新建任务，输入 / 选择 Skill，再提供练习数据、日期和输出位置。菜单名称可能随版本变化。

QoderWork 的官方本地目录为 ~/.qoderwork/skills/。Qoder CLI 的用户级目录为 ~/.qoder/skills/，项目级目录为 .qoder/skills/。这些产品的加载方式分别验证，不能只复制到一个目录就宣称全端可用。

让 Qoder 从成功任务中提炼 Skill
请把刚才成功完成的工单日报任务提炼成一个可复用 Skill。写清何时使用、必需输入、统计口径、输出和停止条件。入口放 SKILL.md，详细规则放 references/，把已经验证的关键数据处理保存到 scripts/。不要创建用不到的空目录。不要依赖这次聊天历史，也不要编造缺失口径。提供正常、变更、异常三类验证样例，我会在新 Chat 中测试。

场景输入应有结果

本练习的脚本已经按确定性案例检查。你自己的 Qoder 是否导入成功、正确选中 Skill 并按流程停止，需要在你的环境验证。

什么时候需要更多目录

tests/ 保存程序测试，例如去重、日期边界和舍入的预期结果。evals/ 保存 Agent 场景，例如新 Chat 的发现、执行和异常处理。它们是可选团队扩展，目录存在不会自动运行。业务口径集中在 references/，实现放 scripts/。简单的文字 Skill 可以只保留 SKILL.md。

把版本、输入文件摘要、处理计数和校验结果留在运行记录中，可以比较改动前后发生了什么。没有实测，不写节省百分比，也不把一次通过当成长期稳定。

常见问题

一定要会 Python 吗？

不需要。你负责说明业务口径、正确结果和异常情况。让 Qoder 或技术同事将容易出错的重复计算保存成脚本，再一起核验。

原 Chat 成功，新 Chat 找不到 Skill？

先确认安装，再输入 / 查找。手动运行成功但自然语言找不到，先改进 description 的任务与触发说明。不要同时把发现失败当成计算错误。

为什么有了脚本还要核验？

脚本也可能使用错误口径或漏掉边界。用独立预期结果和异常案例核对，再检查 Agent 有没有实际调用脚本、有没有跳过校验。

可以直接用真实客户数据吗？

先沿用项目的数据权限与处理约定。教程与练习数据可以公开分享，不能据此推断所有业务输入也能上传。
