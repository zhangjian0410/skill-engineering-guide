Skill Engineering · {{DATE}}

动手做：四步创建并复用 Skill

从还没安装日报 Skill 开始，在这一页完成操作、检查和保存。

开始前 · ① 完成任务 · ② 提炼 · ③ 安装 · ④ 新 Chat · 完成检查

从还没安装日报 Skill 开始

先安装并登录 Qoder，确认账户可用。本页使用 Qoder 的通用模式，它需要能读取练习文件、运行处理并保存结果；不同版本的按钮位置可参考官方入门。Python、依赖和代码由 Qoder 检查配置，不需要先手工安装。全部输入都是虚构工单，可以放心跟练。你负责确认规则、核对数字；处理代码和 Skill 文件交给 AI 整理。

本例的数据已提供，统计口径会在第一步确认，Qoder 需要能运行本地处理脚本。本课无需自己提供模型 API Key，使用 Qoder 账户的可用额度即可。

  1. 普通 Chat 完成任务：得到一份核对正确的日报。
  2. 提炼 Skill：得到自己创建的完整 Skill ZIP。
  3. 安装：在已安装列表中找到它。
  4. 新 Chat 验证：只给数据、日期和输出位置，重做日报。

今天先完成这四步和末尾检查。基础练习不要求生成 tests/evals；想继续完善时，再打开后面的选做进阶跟练。

Chat 指一次对话；Skill 是把处理方法和所需文件保存为可复用能力。第一次还没保存方法，需要把业务规则告诉 AI。提炼、安装之后，日常使用只说本次要处理什么文件、哪一天、结果放哪里。页面上的提示词是示例，可以用自己的话说。

1. 用普通 Chat 完成一次工单日报

现在有什么：只有一份工单数据，还没有你自己的日报 Skill。

你要做什么

  1. 在电脑上新建一个专门的练习文件夹，例如“工单日报练习”。下载工单样例 normal.json，放进这个文件夹。JSON 是这次练习的数据文件，无需手工编辑。
  2. 打开 Qoder，切到通用，点击新的任务。在输入框下方选择工作目录；还没添加过时，点新建工作区 → 点击添加可读写文件夹，选择刚才的练习文件夹，再点创建。确认任务下方显示的是这个文件夹。
  3. 展开下面的提示词，复制到 Chat。此时直接描述任务，不需要选择日报 Skill。

运行中可能出现等待你处理或工具执行确认。看清它要读取的文件、生成的位置或运行的命令；与这次练习一致时点允许一次。确认完成前，任务会暂停等待。这些弹窗在后续步骤也可能出现。若请求读取无关资料或删除文件，点拒绝，再告诉它只处理练习文件、保留验证结果。

应该看到什么

Qoder 返回日报文件的位置和计算过程。打开日报，逐项核对：

核对项本例应得到
统计日期2026-10-10
总工单数5 单
完成 / 待处理3 单 / 2 单
完成工单总耗时195 分钟
完成单平均耗时195 ÷ 3 = 65 分钟

原文件有 7 行：T004 完全重复，保留一条；T006 是 10 月 11 日创建的，本次排除。完成单耗时为 60、45、90 分钟，平均只除以 3 个完成单。这里统计的是 10 月 10 日创建工单的当前状态。

什么叫内容冲突：同一个 ID 出现两次，但日期、状态或耗时不同。例如 T001 一行写 60 分钟、另一行写 90 分钟，AI 无法知道该信哪行，应该列出差异等你确认。不同 ID 是不同工单，不算冲突；同 ID 完全相同只是重复，保留一条即可。

核对一致后再继续。如果平均值出现 39 分钟，让 Qoder 检查是否错误地除以了全部 5 单。如果没读到文件、脚本报错或数字不符，先在这个 Chat 中让它修复并实际重跑，再保存核对后的日报和实际使用的处理代码。

日报核对正确，继续提炼 Skill →

2. 把刚才成功的方法提炼成 Skill

现在有什么：同一个 Chat 中已有输入、规则、处理代码和核对正确的日报。

你要做什么

留在刚才的 Chat，请它把已经做对的方法保存成完整 Skill 包。自己的练习技能统一命名为 my-ticket-daily-report，方便和后面的参考包区分。本步只生成文件，安装在第三步做。

复制：把成功任务提炼成 Skill
{{PROMPT:deep-create}}

应该看到什么

Qoder 给出 my-ticket-daily-report.zip 的文件位置，列出里面保存的内容：

  • SKILL.md：何时使用、需要什么输入、怎样处理、何时停止。
  • 已确认的业务规则：日期筛选、去重和平均耗时的口径。简短规则可写在 SKILL.md，较长时放 references/。
  • 处理脚本：保存已经核对过的计算方法，供下次调用。

另行保留第一步的输入和确认结果，供第四步核对。如果它只在 Chat 中输出了一段说明，让它继续生成完整文件夹并压缩。打开 Skill 说明，检查规则是否与第一步一致；确认脚本只处理指定的本地文件。

以后每次都要遵守的规则、调用脚本的方法、失败时怎样停止，应保存在 Skill 中。下次用户只提供本次参数。若还需要靠长提示词补齐这些内容，先把遗漏补进 Skill。

有了完整 ZIP 才进入安装。业务同事无需自己编写代码，但要确认保存的方法就是刚才做对的方法。

完整 ZIP 已生成，继续安装 →

3. 安装自己刚创建的 Skill

现在有什么：第二步生成的 my-ticket-daily-report.zip，尚未安装。

你要做什么

  1. 在 Qoder 左侧打开扩展 → 技能。
  2. 选择添加技能 → 上传 Skill，选中第二步的 my-ticket-daily-report.zip 并打开。这里上传自己创建的完整包。
  3. 安装成功后，会进入扩展管理 → 技能，在本地 Skill列表中确认 my-ticket-daily-report 和“已安装”标记。同名技能已经存在时，先核对版本，避免覆盖别人的内容。

操作依据：Qoder 官方安装指南。不同版本的按钮名称可能略有差异，找到上传本地技能的入口即可。

应该看到什么

已安装列表里出现你的技能名称。点返回应用，再新建一个任务，在输入框键入 /，建议列表中也能找到它。选中后，输入框会出现 @my-ticket-daily-report 标签。

如果找不到，先检查 ZIP 中是否包含 SKILL.md 和所需脚本。可以把报错给刚才创建文件的 Chat，请它检查包结构。安装成功后进入第四步。

确认已安装，继续在新 Chat 验证 →

4. 在新 Chat 中验证能否复用

现在有什么：已安装的日报 Skill，以及第一步保存的输入和正确结果。

你要做什么

  1. 在电脑上新建一个“工单日报验证”文件夹，只把第一步的 normal.json 复制进去。保留原练习文件夹和正确日报，供核对。
  2. 新建一个全新的任务，不沿用前两步的 Chat。按第一步添加工作区的方法，选择刚建的验证文件夹；确认输入框下方显示这个目录。
  3. 输入 /，选择 my-ticket-daily-report。看到 @my-ticket-daily-report 标签后，在它后面粘贴下面的提示词。输出使用一个新的文件夹。
复制：安装后在新 Chat 中运行
{{PROMPT:deep-verify}}

应该看到什么

Qoder 读取已安装的 Skill，调用其中保存的处理脚本，交付新的日报和核对记录。日报仍为 5 单、完成 3 单、待处理 2 单，完成单平均耗时 65 分钟。

展开回复中的执行工具，查看加载的技能和实际运行的脚本，打开交付文件核对数字。脚本应该来自已安装的 my-ticket-daily-report，而非临时重写或原练习目录的副本。不同产品的安装路径和脚本名可以不同。新的验证文件夹只放输入数据，方便分辨来源。如果它要求你重新讲业务规则，返回第二步补齐 Skill，再更新安装并重试。

再试一次变化和一次异常

  • 下载变化样例 changed.json，放进同一验证文件夹。另开新 Chat，仍选择验证目录和同一个 Skill，把提示词中的输入改为 changed.json、日期改为 2026-10-11，输出改为新的 ticket-changed-run。应该得到 1 单完成、0 单待处理、总耗时 30 分钟、平均 30 分钟。
  • 下载缺字段样例 missing-field.json，放进同一验证文件夹。另开新 Chat，仍选择验证目录和同一个 Skill，把输入改为 missing-field.json，日期仍用 2026-10-10，输出改为新的 ticket-missing-run。应该指出缺失字段并停止，不生成成功日报。

这轮练习完成的标志：普通 Chat 中做对一次，保存成 Skill 并安装；新 Chat 能复用，同口径处理变化，遇到缺字段能停下来。记下输入、日期、实际结果、输出位置和遇到的问题。

四步完成后，按下面的完成检查逐项核对。

卡住时再看：路径、打包和复用问题
  • 找不到输入文件：确认任务下方的工作目录和文件位置。可以补一句“先确认当前工作目录，再找输入文件”，无需每次规定它运行哪条命令。
  • 创建时反复查模板：补一句“直接整理刚才核对过的规则与脚本。SKILL.md 开头用 YAML 的 name 和 description，打包完整文件夹”，再核对 ZIP。
  • 新 Chat 没有使用保存的脚本：把执行记录交给创建 Skill 的 Chat，要求修复入口中的调用方法。更新安装后，另开新 Chat，仍用上面的短任务重测；临时追加脚本路径只算排错。

完成检查：做到这里就完成基础练习

检查项应该看到什么
普通 Chat5 单，完成 3、待处理 2，195 ÷ 3 = 65 分钟
提炼与安装完整 my-ticket-daily-report.zip；安装列表中能找到同名 Skill
新 Chat 正常案实际使用安装包内脚本，结果仍是 5 / 3 / 2、平均 65
变化案 changed.json，2026-10-111 单完成、0 单待处理，平均 30 分钟
缺字段案 missing-field.json指出缺失字段并停止，没有成功日报

保留练习与验证文件夹、完整 Skill ZIP、正确日报和工具执行记录。以后打开 Qoder，在新任务中选择对应工作目录和已安装 Skill，给本次文件、日期和新的输出位置即可；不必重新讲算法。

遇到问题，先把实际输入、预期、实际结果和不含客户信息的执行记录交给 Qoder 修复，再更新安装并重测。不需要通过进阶练习才算完成本课。
